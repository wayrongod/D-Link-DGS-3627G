# D-Link DGS-3627G: восстановление доступа при забытом пароле

[Русский](README.md) · [English](README.en.md)

Небольшой инструмент и пошаговая инструкция для случая, когда у D-Link
DGS-3627G (семейство DGS-3600) неизвестны логин/пароль, а стандартные способы
сброса не помогли.

> **Важно.** Используйте только на оборудовании, которое принадлежит вам
> или на которое у вас есть письменное разрешение владельца. Изменение настроек
> аутентификации и SNMP может привести к потере управления устройством.

## Симптомы, при которых помогает инструкция

- На консоли (`/dev/ttyUSB0`, 115200 8N1) и по telnet не проходит `admin` с
  известными паролями.
- После 3 неудачных попыток вход блокируется на ~60 секунд.
- В ответе telnet вместо обычного `Fail!` появляется что-то вроде:

  ```text
  Timeout or some unexpected error happened on server host(<RADIUS_IP>/RADIUS)!
  The next server host or next method will be used to do authentication, if any.
  Error username or password, RADIUS can not accept NULL string!
  ```

- SNMP-community `public` читает `sysDescr`, а `private` (или другая RW-community)
  позволяет писать.
- HTTP/HTTPS закрыты, открыт только порт 23 (telnet).
- Кнопки Reset / режима password recovery на этой прошивке нет.

## Что понадобится

- Консольный кабель USB-UART и доступ к серийному порту (для диагностики).
- ПК в той же сети, что и коммутатор.
- Установленный net-snmp: `snmpget`, `snmpwalk`, `snmpset`
  (`sudo apt install snmp`).
- Python 3 — для `switch_telnet.py` (внешних библиотек не требует).

Проверено на DGS-3627G, прошивка `Build 3.03.B04`, Boot PROM `1.10-B10`,
H/W `A1`. OID взяты из MIB-архива DGS-3600 Series (`2.80.B31`). На других
прошивках значения могут отличаться — всегда читайте текущие значения перед
изменением.

## Быстрый старт

После того как доступ восстановлен:

```bash
python3 switch_telnet.py
python3 switch_telnet.py 'show account' 'show ports 1-5'
python3 switch_telnet.py -i
python3 switch_telnet.py --host <SWITCH_IP> -u admin -p admin 'show switch'
python3 switch_telnet.py --script commands.txt
```

По умолчанию используется `10.24.54.1`, `admin` / `admin`. Скрипт сам логинится,
автоматически нажимает `a` на постраничном выводе CLI и убирает ANSI-коды.

Формат файла `--script`: по одной команде на строку, пустые строки и строки,
начинающиеся с `#`, игнорируются.

## Пошаговое восстановление

### 0. Подключение

Подключите ПК напрямую к свободному порту коммутатора. Если известен IP —
назначьте адрес из той же подсети, например:

```bash
sudo ip link set eth0 up
sudo ip addr add 10.24.54.100/24 dev eth0
ping -c 1 <SWITCH_IP>
```

### 1. Узнать текущий IP через LLDP

Наклейка на корпусе может показывать старый адрес. Коммутатор сам объявляет
текущий management-IP в LLDP-кадре:

```bash
sudo tcpdump -i eth0 -s 0 -vvv ether proto 0x88cc
```

Ищите `Management Address` в выводе. Если установлен `lldp`:

```bash
sudo lldpcli show neighbors
```

MAC из LLDP должен совпасть с MAC из загрузочного сообщения на консоли.

### 2. Проверить открытые сервисы

```bash
nc -vz <SWITCH_IP> 23
nc -vz <SWITCH_IP> 80
```

Обычно открыт только telnet. Баннер можно посмотреть так:

```bash
nc <SWITCH_IP> 23
```

### 3. Диагноз: виноват RADIUS, а не пароль

Попытка `admin`/`admin` по telnet с задержкой ~30 секунд выдаёт таймаут
RADIUS. Это значит, что коммутатор сначала спрашивает внешний сервер
аутентификации, и до локальных аккаунтов дело не доходит.

Проверьте, что RW-доступ работает (изменение на то же самое значение безвредно):

```bash
snmpget -v2c -c public <SWITCH_IP> 1.3.6.1.2.1.1.4.0
snmpset -v2c -c private <SWITCH_IP> 1.3.6.1.2.1.1.4.0 s "same value"
```

`snmpset` должен выполниться без ошибки — значит запись разрешена. Если `v2c`
не работает — попробуйте `-v1`.

### 4. Прочитать метод-листы входа

У D-Link аутентификация задаётся **method list** — упорядоченным списком
способов проверки. Посмотреть, какой список используется:

```bash
snmpget -v2c -c private <SWITCH_IP> 1.3.6.1.4.1.171.12.5.7.1.2.0
snmpget -v2c -c private <SWITCH_IP> 1.3.6.1.4.1.171.12.5.7.1.1.0
```

- `...7.1.2.0` — telnet login (`tac_login` в нашем случае)
- `...7.1.1.0` — консоль (`default`)

Прочитайте сами списки:

```bash
snmpwalk -v2c -c private <SWITCH_IP> 1.3.6.1.4.1.171.12.5.3
snmpwalk -v2c -c private <SWITCH_IP> 1.3.6.1.4.1.171.12.5.4
```

Колонка `2` = первый метод (`Method1Type`). Для `tac_login` он был `4`
(radius), для `default` — `6` (local).

Индекс строки — это длина имени и его ASCII-коды. Для `tac_login`:

```bash
python3 -c "s='tac_login'; print(len(s), *map(ord, s))"
# 9 116 97 99 95 108 111 103 105 110
```

### 5. Временный обход

**Запишите исходные значения!** Затем временно замените первый метод telnet на
`none` (значение `8`):

```bash
IDX="9.116.97.99.95.108.111.103.105.110"
LOGIN1="1.3.6.1.4.1.171.12.5.3.1.2.$IDX"
ENABLE1="1.3.6.1.4.1.171.12.5.4.1.2.$IDX"

snmpget -v2c -c private <SWITCH_IP> "$LOGIN1"
snmpget -v2c -c private <SWITCH_IP> "$ENABLE1"

snmpset -v2c -c private <SWITCH_IP> "$LOGIN1" i 8
snmpset -v2c -c private <SWITCH_IP> "$ENABLE1" i 8
```

Теперь вход по telnet проходит с любыми логином/паролем, но уровень прав
`user#`. Чтобы получить `admin#`, выполните `enable admin` (пароль любой).

### 6. Создать известный аккаунт и сохранить

```text
show account
create account admin <NEW_USER>
  Enter a case-sensitive new password: <NEW_PASS>
  Enter the new password again for confirmation: <NEW_PASS>
save
```

`save` обязателен — без него изменения живут только в оперативной памяти и
пропадут после перезагрузки.

### 7. Вернуть аутентификацию

Если RADIUS по-прежнему недоступен, ставьте `local`, а не `radius` — иначе вход
снова сломается:

```bash
snmpset -v2c -c private <SWITCH_IP> "$LOGIN1" i 6
snmpset -v2c -c private <SWITCH_IP> "$ENABLE1" i 4
```

Здесь `6` = local для входа, `4` = исходный RADIUS для `enable` (менять не
обязательно: созданный аккаунт уже имеет уровень Admin). Если RADIUS работает —
верните оба значения в исходные.

### 8. Проверить и убрать следы

Откройте **новый** telnet-сеанс и проверьте вход под новыми данными. Только после
этого удаляйте временный аккаунт, если он использовался, и снова `save`.

```bash
python3 switch_telnet.py --host <SWITCH_IP> -u <NEW_USER> -p <NEW_PASS> 'show account'
```

## Справка: OID и значения

| Что | OID | Назначение |
|---|---|---|
| `sysDescr` | `1.3.6.1.2.1.1.1.0` | модель/прошивка |
| `sysLocation` | `1.3.6.1.2.1.1.4.0` | проверка RW-доступа |
| Telnet method list | `1.3.6.1.4.1.171.12.5.7.1.2.0` | имя списка для telnet |
| Console method list | `1.3.6.1.4.1.171.12.5.7.1.1.0` | имя списка для консоли |
| Login method lists | `1.3.6.1.4.1.171.12.5.3.1.*` | таблица способов входа |
| Enable method lists | `1.3.6.1.4.1.171.12.5.4.1.*` | таблица способов `enable` |
| Auth protocol | `1.3.6.1.4.1.171.12.5.1.1.0` | `3` = radius, `2` = local |

Структура таблицы: `1.3.6.1.4.1.171.12.5.<3|4>.1.<column>.<index>`

| Колонка | Смысл |
|---|---|
| `1` | имя списка |
| `2` | `Method1Type` |
| `3` | `Method1ServerGroup` |
| `4` | `Method2Type` |
| `5` | `Method2ServerGroup` |

Наблюдаемые значения `MethodType`:

| Значение | Метод |
|---|---|
| `4` | `radius` |
| `6` | `local` |
| `8` | `none` (вход без проверки) |

> `none` — переходный режим. Используйте его только на время создания аккаунта
> и сразу верните исходное значение. Не оставляйте устройство без
> аутентификации.

## Устранение неполадок

- **Ping не проходит** — неверный IP/VLAN; найдите адрес через LLDP или посмотрите
  загрузку на консоли; попробуйте другой порт.
- **`snmpset` возвращает `notWritable (17)`** — объект не поддерживается прошивкой.
  Не пытайтесь обойти это, используйте method list.
- **После `snmpset` вход не проходит** — вы вернули `radius`, а сервер мёртв;
  поставьте `6` (local).
- **`enable admin` запрашивает пароль** — временно поставьте `8` для enable-списка
  или создайте аккаунт сразу с уровнем Admin.
- **3 неудачные попытки → пауза 60 секунд** — это штатная защита, просто
  подождите.
- **Нет SNMP-инструментов** — `sudo apt install snmp`.
